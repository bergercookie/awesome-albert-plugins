## Description

This is a collection of plugins and themes for the
[Albert](https://albertlauncher.github.io/) launcher. It strives to be up to
date with the latest state of the Albert launcher and its Python API. In case of
an older albert version, see the branches of this repo.

## Installation

Requirements:

- Linux (tested on Ubuntu)
- Albert - [Installation instructions](https://albertlauncher.github.io/docs/installing/)
  - Albert Python Interface: `5.0`

Clone this repository under your local Albert python plugins directory. By
default the that is: `~/.local/share/albert/org.albert.extension.python/modules`.

Then go to the Albert settings and enable the plugins that you are interested in
using. Beware that you may need to install some more dependencies depending on
the plugins you use. These dependencies will probably be pointed out either when
you enable, or when you run the plugin for the first time. Refer to the
directory of the corresponding plugin for more details.

### I don't want to setup all the plugins, just a few

Very well, then after cloning this repo, just symlink or copy the plugin of
choice under your local python plugins directory. For example for the `jira`
plugin:

```sh
cp -r plugins/jira ~/.local/share/albert/org.albert.extension.python/modules/jira
```

After that, enable the plugin from the Albert settings.

## Working on a plugin

Every plugin in this repo is linted, type checked and tested by the same
tooling, all configured in `pyproject.toml` and driven from the `justfile`.
`devbox.json` provisions the toolchain and creates `.venv` on first entry:

```sh
devbox shell         # provisions just/python/dpkg and creates .venv on first entry
just check           # lint + test
just                 # list the recipes
```

Two things about the type check are worth knowing before you add a plugin. The
`albert` module is injected into your plugin's interpreter by the launcher's
plugin loader, so it is not importable; `stubs/albert/__init__.pyi` is what mypy
reads instead, and `test/albert_stub.py` is what pytest imports. If you use an
`albert` name that neither has, `test/test_albert_stub.py` will say so. The four
logging helpers — `debug`, `info`, `warning`, `critical` — are the exception:
they are attached to your plugin's own module by the loader, so call them as
bare globals and do **not** import them from `albert`.

Plugins upstreamed from elsewhere are exempt from some lint rules until someone
tidies them; the exemption is listed per file in `pyproject.toml`, so a new
violation in one of them still fails. New code is not exempt.

Tests live in `plugins/<name>/test/`. Anything that needs the internet is
marked `@pytest.mark.network` and skipped unless you pass `--run-network`; the
reason is in `conftest.py`.

### Packaging

`just deb` builds a single Debian package that installs every plugin under
`/usr/share/albert/python/plugins`. `just deb-smoke` additionally installs it
with `dpkg` and imports every plugin from the installed location — that is the
package test CI runs. See [AGENTS.md](AGENTS.md) for the conventions.
